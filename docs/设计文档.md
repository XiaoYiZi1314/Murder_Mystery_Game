## 1. 项目概述

### 1.1 项目定位

为剧本杀门店「十三雾」开发的**单店自用** PWA 网页应用，同时服务顾客（C 端）与商家（B 端）。

- 不做支付：充值、消费、押金均通过微信私下转账，由商家在后台手动记账。
- 不做 SaaS：系统仅服务本店，无多商户概念。
- 后续演进：小程序（复用后端 API）、短信/邮箱通知。

### 1.2 术语表

| 术语 | 含义 |
|---|---|
| 剧本 | 店内可玩的剧本杀作品（商品） |
| 场次 | 商家/玩家发起的一次排期（时间 + 剧本 + DM + 人数） |
| 锁车 | 场次人数凑齐并收取押金，确认开本 |
| 跳车 | 锁车后玩家取消，押金不退 |
| 拼车 | 散客分别报名同一场次凑人 |
| 妆造 | 剧本配套的服装与妆造展示 |
| DM | 带本主持人（店内员工角色） |
| 开本 | 一场剧本杀正式开始 |

### 1.3 用户规模（容量预估）

- 日访问量约 30 人（小店规模），会员数预计几百级。
- 剧本数、DM 数为十级～百级。
- **结论**：单台腾讯云轻量应用服务器完全够用，无需微服务，单体 Next.js 全栈即可。

## 3. 核心业务流程

### 3.1 场次与预约流程

```
【商家场次】
BOSS/店长/DM 创建场次（草稿）
    → 上架为「开放报名」
    → 顾客报名（替全队报名，占 N 个坑）
        ├─ 未锁车：顾客可自行取消，坑位释放
        └─ 联系顾客微信交押金 → 商家登记「已收押金」→ 场次标记「已锁车」
              ├─ 锁车后跳车：押金不退，登记「跳车」
              └─ 正常开本 →「开本中」→ 结束 →「已结束」

【散客拼车】
开放报名的场次展示「已报 X / 上限 Y，还差 Z 人」
    → 多个散客分别报名凑人 → 人数达标后商家联系交押金锁车

【玩家自主发起预约】
顾客选剧本 + 期望时间 + 人数 → 提交「待审核」预约
    → 商家（DM/店长/BOSS）审核
        ├─ 通过 → 自动生成一个「开放报名」场次
        └─ 拒绝 → 通知顾客
```

**场次状态机**：`草稿 → 开放报名 → 已满/已锁车 → 开本中 → 已结束`；任意非结束状态可被商家标记「已取消」。

**预约（报名单）状态机**：
`已报名（待锁车）→ 已锁车（押金已收）→ 已完成`；
`已报名 → 已取消（顾客自行取消，锁车前）`；
`已锁车 → 跳车（押金不退）`。

### 3.2 充值与消费流程

```
【充值】顾客微信转账给商家 → 店长在后台录入充值
    → 系统加余额 + 记充值流水 + 累计储值额度 → 自动触发会员等级升级

【消费结算】场次结束后
    → 进入「待结算场次」列表
    → 带本 DM（或店长）记账：
        - 支付方式：余额 / 现金 / 微信直接付（均需录入）
        - 系统扣余额（若走余额）+ 记消费流水 + 按 1:1 发积分
    → 场次从待结算列表消失

【押金】收押金登记（金额、经手人）
    → 退还时登记退款金额、经手人（全额退 or 跳车没收）
    → 押金收支进入财务报表对账
```

> 关键规则：
> - **积分人人可得**（散客现金消费也发积分，积分记入其注册账号；消费前需注册登录）。
> - 会员仅是优惠政策载体（折扣、赠礼、免押金等，权益由后台配置）。
> - 评价门槛：账号有**储值记录或积分余额**才能发评价（防刷评）。

### 3.3 评价流程

```
顾客在剧本详情页 / DM 主页评价（打分 + 文字）
    → 敏感词过滤（DFA）
        ├─ 命中 → 不展示（直接拦截）
        └─ 通过 → 实时展示（无需审核）
    → DM / 店长 / BOSS 可回复
    → 店长及以上可删除
    → 顾客可随时删除自己的评价
```

- 玩完一场后进入「评价引导页」：**同时给剧本和 DM 打分**，可跳过。
- 评价展示：系统内 ID（昵称）+ 会员等级徽章 + 打分 + 内容。
- 剧本详情页与 DM 主页各自汇总平均分。

### 3.4 举报流程

```
顾客发起举报（选择类型：DM 服务 / 剧本内容）
    → 对外完全匿名
    → 仅大BOSS可见（列表：举报人真实信息、被举报 DM、举报内容、时间）
    → BOSS 线下处理（系统内不做任何操作，纯只读）
```

### 3.5 礼品兑换流程

```
顾客在店内选礼品 → 店长后台操作兑换
    → 系统扣积分 + 记兑换流水
    → 顾客可在「兑换历史」查看
（线上仅做礼品橱窗展示，不发货、不做线上兑换下单）
```

## 4. C 端功能需求（顾客）

### 4.1 页面结构

```
/                       首页（品牌区 / 推荐剧本 / 场次日历 / DM 速览）
/scripts                剧本列表（分类筛选 + 名称搜索）
/scripts/[id]           剧本详情（需登录）
/costumes               妆造列表
/costumes/[id]          妆造详情
/dms                    DM 列表
/dms/[id]               DM 主页（含评价区）
/sessions               开放报名的场次列表（拼车大厅）
/booking/new            自主发起预约
/me                     个人中心
/me/booking             我的预约
/me/member              会员信息（等级/余额/积分/权益）
/me/wallet              流水（充值/消费/积分/押金/兑换）
/me/history             玩过的剧本
/me/reviews             我的评价
/gifts                  积分礼品橱窗
/report                 举报入口
/login  /register       登录 / 注册（手机号 + 密码）
```

### 4.2 首页

- 品牌视觉区（Logo、店名「十三雾」、氛围图，素材由需求方提供）。
- 推荐剧本位（后台可配置精选）。
- 近期开放报名场次。
- 添加到桌面引导（PWA install prompt，见 §9）。

### 4.3 剧本模块

- **列表页**：公开（未登录可见）；按分类/标签筛选、按名称搜索、排序（最新/价格/评分）。
- **详情页**：需登录。
  - 字段：封面、标题、时长、人数区间、标签、价格、剧本简介、评分。
  - 角色介绍区：角色图 + 角色简介（**非剧透**的背景描述）。
  - 关联模块：该剧本可带的 DM、配套妆造（多对多关联，点击跳转）。
  - 评价区：实名评价（ID + 等级徽章），商家/DM 回复嵌套展示。
  - 操作入口：报名相关场次 / 自主发起预约。

### 4.4 妆造模块

- 独立列表页 + 详情页（多图展示，统一展示比例）。
- 与剧本互相关联展示。

### 4.5 DM 模块

- 独立列表页 + 主页：照片（DM 自上传）、简介、擅长标签、评分、带过的剧本。
- DM 主页下方评价区（打分 + 文字，规则同剧本评价）。

### 4.6 场次与预约

- **场次列表（拼车大厅）**：展示时间、剧本、DM、已报/上限、还差几人；替全队报名时填人数（校验剩余坑位）。
- **自主发起预约**：选剧本 + 期望时间 + 人数 + 备注 → 待审核；通过后自动生成场次。
- **我的预约**：状态展示（待审核/已报名/已锁车/已完成/已取消/跳车）；未锁车可自行取消。
- 预约状态变化通过站内小铃铛通知。

### 4.7 个人中心

- 会员信息：等级（见雾→望遥→栖月→书烬→云影，云影最高）、余额、积分、当前等级权益、距离下一级的储值差额。
- 流水：充值、消费（余额/现金/微信）、积分变动、押金收退、礼品兑换，全记录可查。
- 玩过的剧本：按已结束场次聚合。
- 我的评价：可查看、可删除。

### 4.8 举报

- 入口：底部/侧边菜单。
- 表单：举报类型（DM 服务 / 剧本内容）+ 被举报对象 + 描述（可附截图）。
- 提交后对外匿名，页面提示「已收到反馈」即可，无进度查询。

## 5. B 端功能需求（商家后台）

### 5.1 页面结构

```
/admin                       工作台（今日场次、待办事项）
/admin/sessions              场次管理（创建/编辑/状态流转）
/admin/sessions/pending      自主预约审核
/admin/sessions/settlement   待结算场次
/admin/scripts               剧本管理（增删改查、上下架、角色管理、关联 DM/妆造）
/admin/costumes              妆造管理
/admin/dms                   DM 管理（BOSS 创建 DM 账号；DM 自己编辑主页）
/admin/bookings              报名单管理（锁车/取消/跳车标记）
/admin/deposits              押金登记与退款
/admin/wallet                充值录入 / 消费记账
/admin/gifts                 礼品管理（名称、图片、所需积分、可兑时段）
/admin/reviews               评价管理（删除、回复）
/admin/words                 敏感词库（BOSS）
/admin/reports               举报列表（BOSS，只读）
/admin/finance               财务报表（BOSS）
/admin/logs                  操作日志（BOSS，看 DM 与店长）
/admin/members               会员管理（查询、改余额需留痕）
/admin/levels                会员等级规则与权益配置（BOSS）
/admin/staff                 员工账号管理（BOSS：创建店长/DM 账号）
/admin/settings              店铺设置（商家微信二维码、精选推荐、通知开关）
```

### 5.2 关键后台功能说明

- **创建场次**：选剧本（单选）→ 选主 DM + 备选 DM（多选）→ 时间 → 人数上下限 → 价格（默认取剧本价可改）→ 保存为草稿或直接开放报名。
- **待结算场次**：场次结束自动进入；记账时选支付方式（余额/现金/微信）、金额、发积分确认；提交后消失。带本 DM 优先展示在其工作台。
- **充值录入**：输手机号定位顾客 → 录入金额 → 系统自动加余额、累计储值、判断升级、记流水。
- **财务报表（BOSS）**：
  - 时间维度：日 / 周 / 月汇总。
  - 科目：充值收入、余额消费、现金/微信直接收款、押金收取、押金退还（含跳车没收）、积分兑换。
  - 维度：按剧本、按 DM、按支付方式。
  - 导出：Excel（CSV）。
- **操作日志**：记录所有 B 端敏感操作（改余额、删评价、删/改剧本、押金、记账、场次状态变更等），字段：操作人、动作、对象、前后值摘要、时间、IP。仅 BOSS 可查；顾客操作不记录。
- **通知（小铃铛）**：站内通知。触发点：
  - 顾客侧：预约被通过/拒绝、场次锁车、场次取消、评价被回复、积分/余额变动、等级升级。
  - 商家侧：新自主预约待审核、新报名、人数达标（可锁车）、新举报（仅 BOSS）、待结算提醒。

## 6. 数据库设计

> MySQL 8.0，InnoDB，utf8mb4。以下为核心表结构（字段名以英文，注释中文）。

### 6.1 ER 关系总览

```
users 1──1 dms（员工身份）
users 1──n bookings n──1 sessions n──1 scripts
sessions n──1 dms（主DM）  sessions n──n dms（备选DM，表 session_backup_dms）
scripts n──n dms（script_dms）
scripts n──n costumes（script_costumes）
scripts 1──n script_characters（角色介绍）
scripts 1──n reviews；dms 1──n reviews
users 1──n transactions / points_ledger / deposits / gift_redemptions / reports / notifications
```

（主题色待 Logo 定稿后统一。）

### 9.2 Service Worker（Workbox）

- **Precache**：App Shell（布局、字体、核心样式 JS）。
- **Runtime Cache**：
  - 静态资源/图片：Cache First（配额上限 + LRU 清理）。
  - 页面请求：Network First，失败回退缓存——实现「所有页面离线可访问」（展示最后一次在线数据 + 离线提示条）。
  - `/api` 请求：Network Only（写操作不可离线执行；只读接口可加 stale-while-revalidate）。
- 离线时页面顶部展示「当前离线，展示缓存数据」横幅，写操作按钮禁用。

### 9.3 添加到桌面引导

- 监听 `beforeinstallprompt`，首页展示自定义引导弹窗（iOS Safari 单独出「添加到主屏幕」图文指引）。

### 9.4 Web Push

- 登录后请求通知权限（在用户完成首次预约等有意义时机再询问，避免首次进入就弹权限）。
- 小铃铛（站内通知）为主，Push 为辅：Push 只推关键事件（预约通过、锁车、场次取消）。

## 10. 非功能需求

### 10.1 安全

- 密码 argon2id 哈希；登录接口限流（Redis 计数，同 IP/同手机号 5 次/10 分钟）。
- 全站 RBAC 中间件，B 端接口逐个校验角色（对照 §2.2 矩阵，代码中用集中式权限表声明）。
- 上传文件类型/大小白名单（图片 ≤5MB，sharp 重编码防恶意文件）。
- 举报接口匿名性：对外返回不携带 reporter 信息；查询接口仅 BOSS 角色可联表。
- **明确禁止**「BOSS 登录顾客账号」功能（需求方确认），会员余额调整只能通过留痕的管理操作。

### 10.2 备份与恢复

- 每周日凌晨 mysqldump + uploads 打包 → 本地保留 4 份 → 上传 COS 一份。
- 恢复演练纳入上线检查清单。

### 10.3 性能

- 30 日活/天规模无压力；图片经 sharp 压缩 + 缩略图，列表页加载缩略图。
- 拼车大厅查询走 Redis 缓存（报名/状态变更时主动失效）。

### 10.4 可维护性

- 统一代码规范（ESLint + Prettier + TypeScript strict）。
- `operation_logs` 覆盖所有 B 端敏感操作，便于追责对账。

## 附：需求确认记录（对话摘要）

- 单店自用，非 SaaS；剧本列表公开、详情需登录。
- 剧本展示：封面/时长/人数/标签/角色图与角色简介（非剧透）/价格/简介。
- 场次制 + 玩家自主发起预约（需商家审核，通过后转为开放场次）；场次一场一本、可配主 DM 与备选 DM。
- 报名替全队占坑；散客拼车展示还差人数；锁车靠微信私收押金 + 后台登记；未锁车可自由取消，跳车不退押金；押金退款留痕对账。
- 不做支付、不做超时自动取消；「已确认/锁车」为商家手动操作。
- 举报对象为 DM 服务与剧本内容；仅大 BOSS 可见（含举报人真实信息），系统内只读，线下处理。
- 评价：任何人（有储值或积分）可评任何剧本；玩后引导同时给剧本与 DM 打分可跳过；显示系统 ID + 等级徽章；敏感词直接拦截；店长及以上可删；顾客可随时删自己的评价。
- 会员：等级见雾→望遥→栖月→书烬→云影，储值累计升级（额度后台可配，初版默认 0/500/1500/3000/6000）；权益（折扣/赠礼/免押金）后台可配；充值与消费均由商家后台录入；积分消费 1:1，人人可得；礼品兑换线下进行、后台扣分留痕。
- 财务：完整报表（充值/消费/押金/兑换，多维度），仅 BOSS 可见，支持导出。
- 账号体系：顾客/DM/店长/大BOSS 四级；BOSS 可看员工操作日志，不可登录顾客账号。
- 通知：初期站内小铃铛 + Web Push，后续扩展短信/邮箱。
- 注册：初期手机号 + 密码，后续验证码/小程序。
- 技术：React + Tailwind（C 端）/ Ant Design（B 端）、Next.js、MySQL + Redis、腾讯云轻量服务器，每周备份，自研。
